## 1. 文档目的

本文档沉淀当前已实现的产品范围、页面结构、功能要求、数据规则和验收标准，作为后续开发、内容替换和上线检查的依据。

最初的视觉与调研记录见根目录 [PRD.md](../PRD.md)，技术演进记录见 [TECH_DESIGN.md](../TECH_DESIGN.md)。本文件以当前代码实际行为为准。

## 2. 产品目标

### 2.1 核心目标

1. 招聘方在数秒内判断候选人的经验方向、代表项目和联系方式。
2. 用真实项目展示后端、前端和 AI Agent 能力，而不是只罗列技能标签。
3. 管理员可以独立新增和修改项目内容，无需修改前端代码。
4. 网站本身能够体现工程质量和前端完成度。

### 2.2 成功标准

- 首页第一时间展示个人信息和精选项目。
- 精选项目、经历和联系方式在移动端可完整阅读。
- 作品数据来自接口，已发布与草稿状态隔离。
- 管理入口不出现在公开导航中，写接口受鉴权保护。
- 页面支持键盘操作、减少动效和常见现代浏览器。

### 2.3 非目标

- 不建设开放注册、评论、多管理员协作或多租户 CMS。
- 不提供游客留言表单。
- 不实现重 3D、WebGL 或游戏化导航。
- 不允许在管理端上传任意 HTML。
- 一期不提供作品删除功能。

## 3. 用户与场景

| 用户 | 核心诉求 | 关键页面 |
| --- | --- | --- |
| HR / 招聘方 | 快速了解方向、年限、简历和联系方式 | 首页、经历、联系 |
| 技术面试官 | 了解项目问题、角色、技术方案和结果 | 精选项目、技能、经历 |
| 候选人本人 | 用统一叙事展示经历，并可随时更新作品 | 全部公开页、管理端 |
| 管理员 | 新增、修改、发布或隐藏作品 | `/_studio` |

典型场景：

1. 招聘方从简历链接进入首页，通过项目卡片打开线上作品。
2. 面试官通过 `/projects` 直接进入项目区，继续阅读 `/experience`。
3. 候选人进入隐藏管理端录入项目，切换草稿或发布状态。
4. 访客通过 `/contact` 直接打开站点后联系候选人。

## 4. 信息架构与路由

### 4.1 公开路由

| 路径 | 对应区块 | 说明 |
| --- | --- | --- |
| `/` | 首页 | 个人信息与正文入口 |
| `/projects` | 精选项目 | 第一个正文模块 |
| `/about` | 关于我 | 背景与当前状态 |
| `/skills` | 技能 | 按后端、前端、Agent、工程化分组 |
| `/experience` | 经历 | 时间倒序经历列表 |
| `/contact` | 联系 | 邮箱与社交链接 |

路由使用 Vue Router History 模式，不使用 Hash。未知路径回退首页。

### 4.2 管理路由

默认管理前缀为 `/_studio`，由构建环境变量配置。

| 路径 | 说明 | 鉴权 |
| --- | --- | --- |
| `/_studio/login` | 管理员口令登录 | 否 |
| `/_studio` | 作品列表 | 是 |
| `/_studio/new` | 新增作品 | 是 |
| `/_studio/:id/edit` | 编辑作品 | 是 |

管理路径不会出现在公开导航、页脚或正常公开链接中。管理页面设置 `noindex, nofollow`。

## 5. 页面与交互需求

### 5.1 整体视觉

- 当前主题为暖白底、白色卡片、深炭文字。
- 使用靛紫作为主强调色，青绿作为在线状态与 Agent 标识色。
- 不同项目分类使用低饱和浅色表面区分。
- 不引入整包图标库，使用少量本地 SVG。
- 页面需要保持克制，避免通过高饱和颜色和大面积阴影破坏阅读。

### 5.2 桌面布局

- `>= 1024px` 使用左侧 sticky 身份与导航栏、右侧滚动内容双栏布局。
- 左侧包含姓名、定位、主张、标签、CTA、社交链接和区块导航。
- 右侧第一个内容模块为精选项目。
- 左侧导航保持当前区块高亮，并支持连续快速点击。

### 5.3 移动布局

- `< 1024px` 使用固定顶栏和全屏菜单。
- 菜单打开后锁定页面滚动，支持 Esc 关闭和焦点陷阱。
- 项目卡片由横向布局切换为图片在上、内容在下。
- 页面不得出现横向滚动。

### 5.4 项目卡片

- 精选项目排在普通项目之前。
- 第一条精选项目使用更明显的强调布局。
- 有线上地址时，点击整张卡片在新标签页打开线上地址。
- 没有线上地址但有源码地址时，整卡打开源码地址。
- 两个地址都不存在时，卡片不可点击，并显示内部项目提示。
- 卡片内“在线访问”和“查看源码”分别指向对应链接。
- 卡片支持 Enter 和 Space 打开项目。
- 封面加载失败时显示字母渐变占位。

### 5.5 导航行为

- 点击导航后立即锁定目标区块高亮。
- 平滑滚动途中，高亮不得被其他途经区块覆盖。
- 连续点击多次时，以最后一次目标为准。
- 浏览器前进、后退和刷新应恢复对应区块。
- 页面到达底部时，“联系”必须是当前高亮项。

### 6.1 项目区

- 只请求并展示 `published=true` 的作品。
- 默认排序为精选优先、`sortOrder` 降序、创建时间降序。
- 显示标题、问题、描述、角色、结果、技术栈、分类和封面。
- 包含 `agent` 分类的项目显示 Agent 标识。
- 项目加载失败提供重试；空列表有明确提示。

### 6.2 关于、技能与经历

- 关于部分使用 `profile.ts` 数据，不把长文案写死进模板。
- 技能按 Backend、Frontend、AI Agent、Engineering 分组。
- 经历使用静态数据并保持倒序。
- 简历地址为空时不显示简历按钮，避免空链接。

### 6.3 联系

- 邮箱使用 `mailto:`。
- GitHub 等外链使用新窗口并设置 `noopener noreferrer`。
- 联系区链接到 `/projects`，不使用 Hash。

### 7.1 登录访问控制

- 未登录访问管理路由时跳转登录页并保留原始目标。
- 未授权访问管理 API 返回 `401`。
- 连续 5 次错误口令后返回 `429`。
- 会话有效期 8 小时，API 重启后会话失效。
- 生产环境 Cookie 启用 Secure，前后端应同域部署。

### 7.2 表单行为

- 标题最多 40 字。
- 描述去空白后不能为空。
- 技术栈至少一项、最多 12 项。
- 分类只允许 `agent`、`backend`、`frontend`、`fullstack`。
- 源码、访问、封面地址非空时必须是 HTTP(S) URL。
- 发布状态默认开启，精选状态默认关闭。
- 排序值越大越靠前。

## 9. 非功能需求

### 9.1 性能

- 首页无超大图片和 3D 库。
- 封面图片懒加载。
- 项目列表接口只返回必要字段。
- 生产构建应通过 gzip 后合理控制体积。

### 9.2 可访问性

- 页面使用语义化 `header`、`nav`、`main`、`section`、`footer`。
- 提供跳到主要内容链接。
- 可见 focus ring。
- 项目整卡可用键盘打开。
- 移动菜单支持 Esc、焦点陷阱和滚动锁定。
- 尊重 `prefers-reduced-motion`。
- 正文和背景保持可读对比度。

### 9.3 响应式

| 宽度 | 布局 |
| --- | --- |
| `< 640px` | 单栏、移动顶栏、卡片上下排列 |
| `640px - 1023px` | 单栏加宽、项目卡片横向展示 |
| `>= 1024px` | 左侧 sticky 双栏 |

### 9.4 安全

- 管理口令只通过环境变量提供。
- 口令不以明文写入数据库。
- 管理 Cookie 使用 HttpOnly、SameSite=Lax，生产环境启用 Secure。
- 写接口必须验证会话。
- URL 字段只接受 HTTP(S) 协议。
- Vue 默认转义文本，不支持管理端注入任意 HTML。
- 推荐同域部署，避免宽松 CORS。

### 9.5 兼容性

- 最新 Chrome、Edge、Firefox、Safari。
- 不支持 Internet Explorer。
- History 模式需要服务端 SPA 回退。
